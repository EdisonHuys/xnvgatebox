# 独立控制台（开发版）

此文适用于 `codex/console-capacity-20261017`，正式发布仍为 v0.4.0。控制台与订阅由同一个管理程序提供，不需要额外安装 3x-ui。

## 使用

- 出口总览：分别查看目标、就绪、等待、停止与来源候选数量；主机内存只是资源参考。
- 出口管理：设置目标数量 0–32（安装容量上限可通过 `-max` 降低），程序为新增出口自动建立 VLESS/TCP/REALITY 入站。默认保留现有出口策略，新国家条件只用于新增出口。软件上限不承诺 VPS 同时承载 32 个出口；建议逐步增加并观察资源。
- 我的订阅：默认包含全部就绪且启用的内置入站，并包含今后新增的出口；也可选择编号生成固定范围订阅。复制原链接到客户端，刷新订阅同步数量和名称。等待或停止的出口暂不输出；如果范围内没有就绪入站，返回非 200，让客户端保留上次配置。保留的旧节点在服务端仍受到阻断保护。
- 候选节点：搜索、按来源国家及检测状态筛选，勾选后排队测试。候选列表不是“已验证可用列表”。
- 设置：管理密码、路径和端口；高级管理入口保留完整入站、客户端及导出功能。默认浅色，可切换深色。顶部仅使用 xnvgatebox 品牌，开源致谢及许可继续保留。

改变数量保留已存在出口的端口与凭据。减少数量从最大编号开始移除；对应内置入站留存并显式阻断，再增加相同编号时复用其端口及客户端密钥。移除后重新创建的 SOCKS 认证属于新 Slot 生命周期，可能重新生成。数量计划写入私有 `console.json`，重启恢复计划，故障后重试尚未完成的分配或绑定。

国家没有合适 IP 是上游供给或可达性条件，不要求某国随时成功。等待出口保留策略和编号，绝不跨国凑数或直连母机。类型缺少证据时如实显示 unknown，不能称为家宽。

## 名称和二维码

自动名称来自当前已核验 OpenVPN 实际出口国家，例如 `🇯🇵 日本 · 01`；同国家换 IP 不改变这个名称。缺少可信国家时显示“待验证”。同一出口有多个入站/客户端时追加区分字段；可在出口管理中切换自定义名称。名称通过真实订阅链接的 fragment 输出，不只是管理页装饰。

二维码由本机管理服务生成，不调用外部二维码网站；生成接口也需要管理员登录。订阅口令和二维码均属于私有访问凭据。

## 刷新与检测的区别

“刷新候选池”触发 VPS 上同一个 Python Pool Builder 从官方来源重新采集，成功后重读清单；失败保留旧清单并报告失败。使用与定时器一致的文件锁，已有任务运行时不会并发覆盖。列表数量是完整解析官方本次公开响应后的候选数，不等于 VPN Gate 全球服务器总数；会随时间变化。

“检测当前出口”使用现有 SOCKS 对两个 HTTPS Echo 做实际出口核验，检查结果必须一致且等于该出口记录；不重启健康隧道。发现出口变化会阻断，避免回落母机。

已经作为运行出口的候选复用现有 SOCKS 检测，避免对同一上游重复拨号影响现有会话。其他“检测候选节点”在独立临时 namespace 建立真实 OpenVPN，再通过独立 SOCKS 核验两个 HTTPS Echo，匹配基线、画像和 actual IP。它不是 ping 或 TCP 端口测试。使用保留的诊断编号 240，不占用户 1–32 的身份和监听；任务串行，共享最多两个建连并发的预算。取消后清理临时连接、namespace、监听和私有临时文件，不把未完成结果写成成功。

检测展示进度、时间和失败原因。15 分钟后或来源 OpenVPN 配置变化时，旧诊断结果标记过期；历史成功不代表节点现在一定可用，正式出口建立时仍重新验活。服务停止时取消检测和刷新并等待清理；异常退出后，启动时仅清理本实例保留诊断编号和私有临时目录。残留进程须同时匹配 OpenVPN、私有检测配置路径及 namespace，使用 pidfd 固定进程身份后才结束。检测记录 `checks.json` 只是辅助观察，不能在重启后恢复 healthy 状态。

内置 Xray 的入站/路由配置变更仍可能整体重启 Xray，短暂中断其他客户端连接；纯检测和无变化的数量对账不触发此操作。CF 保持暂停，测试与安装只操作本项目。
