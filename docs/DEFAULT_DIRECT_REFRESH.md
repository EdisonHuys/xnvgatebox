# 首次直出与候选刷新反馈

[v0.9.2](https://github.com/hanhaoops/xnvgatebox/releases/tag/v0.9.2) 已发布。25 项安装器回归、控制台 Node、Python 3.9/3.12、Go/race 及 [正式包六系统验收](https://github.com/hanhaoops/xnvgatebox/actions/runs/40065479139) 全部通过；发布与公开附件校验见 [脱敏证据](evidence/github-direct-refresh-20261024.json)。

从 v0.9.2 起，首次安装默认开启本机直出。刷新候选显示正在处理、等待时间和明确结果，失败不会被“尚未取得清单”提示覆盖。

- 仅在全新受管工作目录首次安装后，通过已认证本地 API 创建带客户端身份的 VLESS/REALITY 本机直出；初始化失败按部署事务回滚。已有配置、关闭状态、端口和身份保留，不因升级自动开启直出。
- 默认直出仍是独立出口，不成为 VPN Gate 或第三方 SOCKS5 的故障回落；外部 SOCKS5 不默认开放。
- 刷新点击后立即进入运行状态，展示不确定进度条和实际等待秒数，不编造完成百分比。结束展示成功候选数量或超时、来源不可用、正在构建、配置错误等安全原因码。
- 无候选时也优先展示本次刷新失败原因；明确区分候选获取和节点连通检测，获取成功不称 VPN 已验证。
- 后端只记录固定阶段/错误码/候选数量，不返回进程原始输出、配置 URL、私有凭据或管理路径。
- 回归覆盖首次默认启用、初始化失败恢复、既有明确关闭状态保留、刷新开始与去重、超时/失败清理、错误私密性以及网页从运行到成功/失败的状态变化。六系统继续验收真实默认直出订阅 HTTPS 和更新保留。

网页手动刷新与 systemd 定时任务是两个触发入口。手动刷新结果可查看管理服务内带固定标签的日志，以下命令只筛选刷新记录：

```sh
journalctl -u xnvgatebox-fanout.service --grep='\[pool-refresh\]' --no-pager -n 30
```

候选数量不变不代表刷新失败，也不能仅凭安装成功判断来源可达；应结合本次结果与成功清单时间。来源请求超时的环境仍可独立使用直出和第三方 SOCKS5，故障不自动回落，unknown 不视为住宅。
